# Deploying the Moneo Extension

How Supabase config is used in different environments and how to prepare the extension for release (e.g. Chrome Web Store).

---

## How the extension gets the Supabase key

| Environment | How the key is provided | Who sets it |
|-------------|-------------------------|-------------|
| **Local dev** | You create `supabase.config.json` from the template and add your URL + anon key. The background script loads it on startup. | You (once per machine) |
| **Release / Chrome Web Store** | You generate `supabase.config.json` from **env vars** right before packaging. The packaged zip includes that file, so installed users get the key with no setup. | You or CI (at build time) |

The anon key is **safe to ship** in the extension: Supabase’s anon key is meant to be public and is protected by Row Level Security (RLS), not by keeping the key secret.

---

## Local development (no deploy)

1. Copy the template and add your keys:
   ```bash
   cp supabase.config.template.json supabase.config.json
   ```
2. Edit `supabase.config.json` with your Supabase URL and anon key.
3. Load unpacked in Chrome. The background script reads the file and stores the values; no further setup.

`supabase.config.json` is gitignored and must not be committed.

**Optional – local env file:** Copy `.env.example` to `.env` and set `SUPABASE_URL` and `SUPABASE_ANON_KEY` for running `npm run prepare-release` locally. `.env` is gitignored; never commit it.

---

## Release / packaging (Chrome Web Store or zip)

When you **deploy** (package the extension for distribution), there is no local `supabase.config.json` in the repo. Generate it at **build time** from secrets so the packaged extension contains the config.

### Option A: Run the script locally (manual release)

1. Set your Supabase URL and anon key in the environment, then run the prepare script:
   ```bash
   export SUPABASE_URL="https://YOUR_PROJECT_REF.supabase.co"
   export SUPABASE_ANON_KEY="eyJ..."   # anon key from Supabase Dashboard → Settings → API
   node scripts/prepare-release.js
   ```
2. This creates `supabase.config.json` in the project root (still gitignored).
3. Package the extension (zip the folder, or use Chrome’s “Pack extension”). The zip must include `supabase.config.json`.
4. Upload that zip to the Chrome Web Store (or distribute it).
5. Optionally delete the local `supabase.config.json` after packaging so you don’t accidentally commit it:  
   `rm supabase.config.json`

### Option B: GitHub Actions (CI/CD)

A workflow is set up to build the extension using **repository secrets** (keys never in code or logs).

1. **Add secrets** (once per repo):  
   GitHub → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**  
   - `SUPABASE_URL` = your Supabase project URL (e.g. `https://xxxx.supabase.co`)  
   - `SUPABASE_ANON_KEY` = your Supabase anon (public) key  

2. **Run the workflow:**  
   Push to `main`/`master` or go to **Actions** → **Build extension** → **Run workflow**.

3. **Get the built extension:**  
   Open the completed run → **Artifacts** → download **moneo-extension** (zip). Use this for Chrome Web Store or local “Load unpacked” (unzip first).

See **.github/README.md** for step-by-step secret setup and artifact download.

### What gets packaged

The zip you upload should contain everything a user (or the store) needs:

- `manifest.json`
- `src/` (all scripts)
- `styles/`, `icons/`, `popup.html`, `popup.js`, etc.
- **`supabase.config.json`** (generated by `scripts/prepare-release.js` from env, not from the repo)

So when the extension is installed from the store, it already has `supabase.config.json` with your project URL and anon key; the background script loads it and no user setup is required.

---

## Checklist before publishing

- [ ] Edge Function and secrets are set in Supabase (`OPENAI_API_KEY`, `BRAVE_API_KEY`, etc.).
- [ ] `SUPABASE_URL` and `SUPABASE_ANON_KEY` are set in CI (or in your shell for manual release).
- [ ] `node scripts/prepare-release.js` is run before zipping so `supabase.config.json` exists in the build output.
- [ ] The packaged zip includes `supabase.config.json` and is uploaded to the Chrome Web Store (or distributed).
- [ ] You never commit `supabase.config.json` or put real keys in `src/config.js`; the repo stays key-free.

---

## Summary

- **Repo:** No Supabase keys committed. Local dev uses a hand-created `supabase.config.json` (from template).
- **Deployed extension:** Keys are injected at **build/release time** via env vars and `scripts/prepare-release.js`; the same loading path (background reads `supabase.config.json`) works for both dev and production.
